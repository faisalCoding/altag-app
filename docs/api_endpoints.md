# دليل واجهات برمجة التطبيقات (API Reference) - المعلم والتحضير

يوفر هذا المستند توثيقاً للمنافذ البرمجية (API Endpoints) الخاصة بتسجيل دخول المعلمين وتحضير الطلاب.

---

## 1. تسجيل دخول المعلم (Teacher Login)

- **المسار:** `/api/teacher/login`
- **البروتوكول:** `POST`
- **الترويسة (Headers):** 
  - `Accept: application/json`
  - `Content-Type: application/json`

### جسم الطلب (Request Body):
```json
{
  "email": "teacher@example.com",
  "password": "password",
  "device_name": "iphone_15"
}
```
*(ملاحظة: حقل `device_name` اختياري ويستخدم لتسمية توكن التوثيق)*

### رد النجاح (200 OK):
```json
{
  "token": "1|abcdef123456...",
  "teacher": {
    "id": 1,
    "name": "معلم تجريبي",
    "email": "teacher@example.com",
    "phone": "123456789",
    "is_approved": true
  }
}
```

### رد الخطأ - بيانات خاطئة (401 Unauthorized):
```json
{
  "message": "بيانات الدخول غير صحيحة."
}
```

### رد الخطأ - حساب غير مفعل (403 Forbidden):
```json
{
  "message": "لم يتم تفعيل حسابك من قبل الإدارة بعد."
}
```

## 2. عرض الحلقات والتحضير (Fetch Circles & Students)

يستخدم لجلب قائمة الحلقات المرتبطة بالمعلم، وقائمة طلاب الحلقة المختارة مع حالة حضورهم الحالية، أو لمزامنة البيانات محلياً.

- **المسار:** `/api/teacher/attendance`
- **البروتوكول:** `GET`
- **الترويسة (Headers):**
  - `Accept: application/json`
  - `Authorization: Bearer <TOKEN>`

### معاملات الاستعلام (Query Parameters):
- `circle_id` (اختياري - integer): معرف الحلقة المراد جلب طلابها.
- `date` (اختياري - string): تاريخ التحضير بتنسيق `YYYY-MM-DD` (القيمة الافتراضية: تاريخ اليوم).
- `last_synced_at` (اختياري - string): توقيت آخر مزامنة بتنسيق ISO 8601 (مثل `2026-06-21T18:00:00Z`). عند إرساله، سيعيد الـ API السجلات المحدثة أو المضافة بعد هذا التوقيت فقط لجميع حلقات المعلم.

### رد النجاح - الاستعلام العام (بدون تحديد حلقة وبدون مزامنة):
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "selected_circle": null,
  "students": []
}
```

### رد النجاح - عند إرسال معرف الحلقة والتاريخ:
`/api/teacher/attendance?circle_id=1&date=2026-06-21`
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "selected_circle": {
    "id": 1,
    "name": "حلقة الإيمان",
    "description": "مخصصة للمرحلة الثانوية"
  },
  "students": [
    {
      "id": 5,
      "name": "طالب تجريبي",
      "circle_id": 1,
      "attendance_status": "present"
    }
  ]
}
```
*(ملاحظة: قيم `attendance_status` الممكنة هي: `present`, `absent`, `late`, `excused` أو نص فارغ `""` في حال لم يحضر الطالب بعد).*

### رد النجاح - عند المزامنة التدريجية (باستخدام `last_synced_at`):
`/api/teacher/attendance?last_synced_at=2026-06-21T18:00:00Z`
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "students": [
    {
      "id": 5,
      "name": "طالب تجريبي",
      "circle_id": 1,
      "attendance_status": ""
    }
  ],
  "attendances": [
    {
      "id": 10,
      "student_id": 5,
      "teacher_id": 1,
      "circle_id": 1,
      "date": "2026-06-21",
      "status": "present",
      "notes": null,
      "updated_at": "2026-06-21T18:30:00.000000Z"
    }
  ],
  "server_time": "2026-06-21T18:45:25.000000Z"
}
```
*(ملاحظة: حقل `attendance_status` في الطلاب المسترجعين عند المزامنة التدريجية يكون فارغاً، حيث يتم الاعتماد على مصفوفة الـ `attendances` المرفقة لبناء السجل المحلي).*

### رد الخطأ - حلقة غير تابعة للمعلم (403 Forbidden):
```json
{
  "message": "غير مصرح لك بالوصول لهذه الحلقة."
}
```

## 3. رصد وحفظ حضور الطلاب (Mark Student Attendance)

يستخدم لحفظ أو تحديث حضور وغياب الطلاب في حلقة وتاريخ محددين، أو لمزامنة البيانات محلياً.

- **المسار:** `/api/teacher/attendance`
- **البروتوكول:** `POST`
- **الترويسة (Headers):**
  - `Accept: application/json`
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>`

### جسم الطلب (Request Body):

يدعم المنفذ طريقتين للطلب لضمان توافقية الأنظمة:

#### الطريقة الأولى: الإرسال البسيط لمجموعة طلاب (Associative Array)
```json
{
  "circle_id": 1,
  "date": "2026-06-21",
  "records": {
    "5": "present",
    "6": "late",
    "7": "absent"
  }
}
```
*(ملاحظة: هيكل الـ `records` هو عبارة عن قاموس يربط معرف الطالب `student_id` بحالة الحضور المقررة له: `present`, `absent`, `late`, `excused`).*

#### الطريقة الثانية: المزامنة الدفعية للمحلي أولاً (Local-First Batch Sync)
تسمح بمزامنة سجلات لتواريخ وحلقات مختلفة مع دعم فرز التعارضات بالتوقيت:
```json
{
  "records": [
    {
      "student_id": 5,
      "status": "present",
      "date": "2026-06-21",
      "updated_at": "2026-06-21T18:30:00Z"
    },
    {
      "student_id": 6,
      "status": "absent",
      "date": "2026-06-20",
      "updated_at": "2026-06-21T18:25:00Z"
    }
  ]
}
```
*(ملاحظة: يقوم النظام بتطبيق خوارزمية **"آخر كتابة تفوز" (Last-Write-Wins)** بمقارنة `updated_at` الممررة مع نظيرتها في قاعدة البيانات. يتم تخطي التحديث إذا كانت النسخة على السيرفر أحدث).*

### رد النجاح (200 OK):
```json
{
  "message": "تم تسجيل حضور الطلاب بنجاح.",
  "synced_attendances": [
    {
      "id": 10,
      "student_id": 5,
      "teacher_id": 1,
      "circle_id": 1,
      "date": "2026-06-21",
      "status": "present",
      "notes": null,
      "updated_at": "2026-06-21T18:45:25.000000Z"
    }
  ]
}
```

### رد الخطأ - عدم صلاحية الحلقة (403 Forbidden):
```json
{
  "message": "غير مصرح لك بالوصول لهذه الحلقة."
}
```

# الإصدار الأول (v1) — تطبيق المعلم بالعمل دون اتصال

صُمّم هذا الإصدار لتطبيق الجوال الذي يحفظ بياناته كاملةً على الهاتف ويعمل دون اتصال، ثم يزامنها مع الخادم. المنافذ السابقة أعلاه باقية كما هي.

- **الفكرة:** يجلب التطبيق نسخة كاملة من بياناته من `/sync` ويستبدل بها نسخته المحلية في كل مزامنة، ويحفظ تعديلات التحضير في طابور على الهاتف ثم يرسلها إلى `/attendance/changes`.
- **الترويسة (Headers)** لجميع المنافذ:
  - `Accept: application/json`
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>` (عدا تسجيل الدخول)
- **التاريخ:** جميع التواريخ بتنسيق `YYYY-MM-DD`، و«اليوم» يُحسب بتوقيت الرياض (`Asia/Riyadh`).

## 1. تسجيل الدخول

- **المسار:** `/api/v1/teacher/login`
- **البروتوكول:** `POST`
- **الحد:** ٥ محاولات في الدقيقة لكل بريد وعنوان IP.

```json
{
  "email": "teacher@example.com",
  "password": "password",
  "device_name": "Pixel 9"
}
```

### رد النجاح (200 OK):
```json
{
  "data": {
    "token": "1|abcdef123456...",
    "teacher": { "id": 1, "name": "معلم تجريبي", "email": "teacher@example.com", "phone": "0500000000", "is_approved": true }
  }
}
```

ردود الخطأ: `401` لبيانات خاطئة، و`403` لحساب لم تُفعّله الإدارة. الرمز لا تنتهي صلاحيته حتى يُسجَّل الخروج.

## 2. تسجيل الخروج

- **المسار:** `/api/v1/teacher/logout`
- **البروتوكول:** `POST`

يُلغي الرمز المستخدم في الطلب فقط، وتبقى أجهزة المعلم الأخرى مسجّلة.

## 3. جلب البيانات للعمل دون اتصال (Sync)

- **المسار:** `/api/v1/teacher/sync`
- **البروتوكول:** `GET`

يعيد كل ما يحتاجه التطبيق لتحضير الطلاب دون اتصال:

- `today`: تاريخ اليوم بتوقيت الرياض.
- `window`: نطاق البيانات؛ يبدأ `from` من أول الشهر الهجري السابق، وينتهي `to` بعد اليوم بأربعة عشر يوماً حتى يستمر التحضير إن انقطع الاتصال.
- `circles`: حلقات المعلم، ولكل حلقة `require_edit_reason` (هل يُطلب سبب للتعديل في غير يوم الجلسة) و`working_days` (أيام الحلقة في التقويم ضمن النطاق) و`whatsapp_group_url` (مجموعة الواتساب التي تُفتح بعد نسخ رسالة الغياب: مجموعة الحلقة إن حدّدها المشرف، وإلا مجموعة مرحلتها، و`null` إن لم توجد فتُنسخ الرسالة فقط) و`period` (فترة الحضور التي تعيشها مرحلة الحلقة لبطاقة الطالب: الفترة التي تشمل اليوم، وإلا آخر فترة بدأت قبله، و`null` إن لم توجد فترة للمرحلة؛ والفترة المربوطة بمراحل لا تخص إلا مراحلها، والفترة التي لا تسمي مرحلة تخص الجميع. فيها `start` و`end` (أو `null` لفترة مفتوحة) و`working_days` أيام المرحلة في التقويم من بداية الفترة حتى اليوم أو حتى نهايتها إن انتهت).
- `students`: طلاب الحلقات المعتمدون مع `joined_at` وسجل حالاتهم `status_histories`، لتحديد الأيام التي يجوز تحضيرهم فيها، ومع أرقام التواصل في بطاقة الطالب: `phone` (جوال الطالب) و`guardian_name` و`guardian_phone` (اسم ولي الأمر وجواله)، وكلها `null` إن لم تُسجَّل.
- `attendances`: سجلات حضور هؤلاء الطلاب من بداية النطاق حتى اليوم، أياً كانت الحلقة التي سجّلتها.
- `attendance_history`: حضور هؤلاء الطلاب قبل النطاق للعرض فقط في بطاقة الطالب: من أقدم `period.start` بين حلقات المعلم حتى اليوم السابق لـ `window.from` (أيام النطاق نفسه في `attendances`)، مرتبة بالطالب ثم التاريخ، ولكل سجل `student_id` و`date` و`status` فقط. تأتي فارغة إن لم تكن لأي حلقة فترة أو بدأت الفترة داخل النطاق.
- `days`: قراءة كل يوم في النطاق بالتاريخ الهجري (أم القرى).
- `labels`: مسميات حالات الحضور وحالات الطالب.
- `competitions`: المسابقة الأساسية للتسجيل لكل حلقة — مسابقة المشرف المعيّنة كأساسية للحلقة، وإلا مسابقة المعلم الخاصة المعيّنة كأساسية — مع بنودها (`criteria`) وفترتها، وهل النقاط الإضافية مفعّلة فيها، وحلقات المعلم التي تُرصد فيها (`circle_ids`).
- `scores`: البنود الممنوحة للطلاب داخل النطاق؛ وجود السجل يعني أن البند ممنوح.
- `extra_points`: النقاط الإضافية داخل النطاق، ولكل منها `id` على الخادم و`uuid` إن أُنشئت من التطبيق.
- `pages`: الشاشات الإضافية المتاحة للمعلم الآن — `tasmeeh` (صفحة التسميع) و`student_exams` (صفحة اختبارات الطلاب) و`plan_creator` (صفحة إنشاء الخطط). يُظهر التطبيق تبويب التسميع فقط عندما تكون `tasmeeh` صحيحة. قوائم التسميع (`tasmeeh_*` و`free_recitations`) تأتي فارغة إن كانت صفحة التسميع موقوفة، أما قوائم الاختبارات (`exam_levels` و`exams` و`exam_suggestions`) فتُرسل إن كانت إحدى الصفحتين مفعّلة، ولا تأتي فارغة إلا إن أُوقفت الصفحتان معاً: فبطاقة التسميع تعرض عدد أجزاء الاختبار القادم للاطلاع حتى لو أُوقفت صفحة الاختبارات، وتبقى الجدولة مشروطة بصفحة الاختبارات (انظر §8).
- `tasmeeh_plans`: خطط القرآن النشطة المعتمدة (حفظ، مراجعة، حفظ ومراجعة) لطلاب المعلم، ولكل خطة `position` يرتّب خطط الطالب الواحد من الأحدث (0) كما في صفحة التسميع. لا تُرسل خطة بلا أيام، ولا خطة أنشأها الطالب ولم يعتمدها المعلم بعد.
- `tasmeeh_days`: كل أيام تلك الخطط مرتبة، ولكل يوم مقطع الحفظ `hifz` ومقطع المراجعة `review` بالسورة والآية (`{from: {surah, verse}, to: {surah, verse}}`)، أو `null` إن لم يكن الجزء في الخطة. الخطة لا تتغير أبداً بالتسميع.
- `tasmeeh_cells`: ما سجّله المعلمون لكل جزء من يوم: `grade` من 0 إلى 3 (0 = لم يسمع، 1 = مقبول، 2 = جيد، 3 = ممتاز، و`null` = لم يُقيَّم)، و`recited` ما سمّعه الطالب فعلاً إن خالف مقطع اليوم (`null` = سمّع المقطع نفسه)، و`graded_on` يوم التقييم بتوقيت الرياض، و`updated_by` آخر من سجّل. لا تُرسل خانة فارغة.
- `free_recitations`: التسميع الحر داخل النطاق (لطالب بلا خطة)، واحد لكل طالب وجزء ويوم، بالحقول نفسها إضافة إلى `id` و`uuid` و`date`.
- `exam_levels`: مستويات الاختبار مرتبة بعدد الأجزاء `juz_count` (وهو الرقم الذي يظهر في مربع الاختبار)، والمستويات بلا نهاية في الآخر.
- `exams`: كل اختبارات الطلاب المعلّقة (`pending`) أياً كان تاريخها؛ فالاختبار الذي مضى يومه دون نتيجة ما زال اختبار الطالب القادم.
- `exam_suggestions`: المستوى المقترح لكل طالب: أصغر مستوى عدد أجزائه أكبر من أكبر مستوى اجتازه.
- `calendar_periods`: فترات الحضور التي تخص مراحل حلقات المعلم (المربوطة بإحدى مراحلها، والتي لا تسمي مرحلة)، ليرتّب التطبيق أيام خطة جديدة دون اتصال بقواعد الموقع نفسها. لكل فترة `name` و`start` و`end` (أو `null`) و`weekdays` (١ = الأحد … ٧ = السبت، والفارغة تعني كل أيام الفترة) و`stage_ids` (الفارغة تعني كل المراحل) و`extra_dates` و`excluded_dates`. تأتي فارغة إن كانت صفحة إنشاء الخطط موقوفة.
- `active_plan_counts`: عدد الخطط المفعّلة لكل طالب، مفتاحه معرّف الطالب، ولا يُذكر فيه طالب بلا خطة؛ يعرض التطبيق به خيار «إيقاف الخطط السابقة». يأتي `{}` إن كانت صفحة إنشاء الخطط موقوفة.
- `hijri_months`: الأشهر الهجرية من الشهر الذي يقع فيه أقدم تاريخ يعرضه التطبيق — `window.from`، أو أقدم `period.start` إن سبقه، أو أول يوم في `tasmeeh_days` إن سبقهما — حتى أبعد الشهرين: الشهر الخامس بعد الشهر الحالي (أي الشهر الحالي وخمسة بعده كما في تقويم الاختبار)، أو الشهر الذي يقع فيه آخر يوم في `tasmeeh_days`. فكل يوم من أيام الخطط المرسلة يقع داخل هذه الأشهر، ويعرض التطبيق الخطة كاملة جدولاً بالتاريخ الهجري. ولا تمدّ أيامُ الخطط النطاقَ أكثر من سنتين قبل اليوم أو بعده (`PLAN_MONTHS_REACH_YEARS`)؛ فتاريخ أبعد من ذلك خطأ في الإدخال، ويظهر في التطبيق بالتاريخ الميلادي. لا تمدّ الخطط النطاق إلا حين تُرسل، أي حين تكون صفحة التسميع مفعّلة للمعلمين؛ وإلا بقي من الأقدم بين `window.from` و`period.start` حتى الشهر الخامس بعد الشهر الحالي. لكل شهر `first_day` (اليوم الميلادي الذي يبدأ فيه) و`length`، ليرسم التطبيق تقويم اختيار تاريخ الاختبار ويقرأ تواريخ مربعات الحضور في بطاقة الطالب وأيام الخطط دون حسابات أم القرى. ويبقى تقويم اختيار تاريخ الاختبار لا يتجاوز الشهر الخامس بعد الشهر الحالي (`CALENDAR_MONTHS` = ٦ أشهر بالشهر الحالي) وإن امتدت الأشهر المرسلة أبعد منه؛ يقصره التطبيق على ذلك بنفسه. أما تسميع أقدم من هذه الأشهر في سجل الطالب فيظهر بالتاريخ الميلادي.

```json
{
  "data": {
    "today": "2026-10-01",
    "window": { "from": "2026-08-14", "to": "2026-10-15" },
    "teacher": { "id": 1, "name": "معلم تجريبي", "email": "teacher@example.com", "phone": null, "is_approved": true },
    "circles": [
      {
        "id": 3, "name": "حلقة الإيمان", "description": null,

        "period": { "start": "2026-08-02", "end": "2027-01-07", "working_days": ["2026-08-02", "2026-08-03", "…", "2026-10-01"] }
      }
    ],
    "students": [
      {
        "id": 5, "name": "طالب تجريبي", "circle_id": 3, "status": "active",
```

## 4. إرسال تعديلات التحضير

- **المسار:** `/api/v1/teacher/attendance/changes`
- **البروتوكول:** `POST`
- **الحد:** حتى ٥٠٠ تعديل في الطلب الواحد.

```json
{
  "changes": [
    {
      "id": "2f1c9a4e-8b7d-4c1e-9f3a-6d2b1e0c5a7f",
      "student_id": 5,
      "date": "2026-09-30",
      "status": "present",
      "base_status": null,
      "reason": "نسيت التحضير في يومه",
      "edited_on": "2026-10-01"
    }
  ]
}
```

- `id`: معرّف UUID يولّده الهاتف لكل تعديل، ويُعاد في الرد لربط النتيجة بالتعديل.
- `status`: الحالة الجديدة، أو `null` لمسح التحضير.
- `base_status`: الحالة التي رآها الهاتف على الخادم عند التعديل (أو `null` إن لم يكن هناك تسجيل). **حقل إلزامي** ولو كانت قيمته `null`.
- `reason`: سبب التعديل، ويُطلب إذا كان اليوم المُحضَّر غير يوم التعديل وكانت مرحلة الحلقة تشترطه.
- `edited_on`: اليوم الذي أجرى فيه المعلم التعديل على هاتفه؛ فالتحضير الذي يُسجَّل في يومه دون اتصال ثم يُزامَن لاحقاً لا يُعدّ تعديلاً في غير يوم الجلسة.

تُطبَّق على كل تعديل قواعد صفحة التحضير الشهرية نفسها، ويُسجَّل في سجل التعديلات كما لو أُجري من الصفحة.

### رد النجاح (200 OK):
```json
{
  "data": {
    "results": [
      { "id": "2f1c…", "result": "applied", "attendance": { "student_id": 5, "circle_id": 3, "date": "2026-09-30", "status": "present", "updated_at": "…", "updated_by": "معلم تجريبي" } },
      { "id": "7a3d…", "result": "conflict", "attendance": { "student_id": 6, "circle_id": 3, "date": "2026-09-30", "status": "absent", "updated_at": "…", "updated_by": "معلم آخر" } },
      { "id": "c91e…", "result": "rejected", "code": "reason_required", "message": "يجب إدخال سبب التعديل عند التحضير في غير يوم الجلسة." }
    ],
    "server_time": "2026-10-01T07:40:00.000000Z"
  }
}
```

**أنواع النتائج:**

- `applied`: حُفظ التعديل، أو كان الخادم يحمل القيمة نفسها مسبقاً. لذلك فإن إعادة إرسال تعديل حُفظ من قبل لا تكرّره.
- `conflict`: تغيّرت القيمة على الخادم منذ آخر مزامنة (من معلم آخر أو من صفحة الويب) إلى قيمة ثالثة. لا يُحفظ التعديل، ويُعاد سجل الخادم الحالي ليعرض التطبيق القيمتين على المعلم فيختار. لاعتماد قيمة الهاتف يُعاد إرسال التعديل بـ `base_status` يساوي قيمة الخادم.
- `rejected`: رُفض التعديل لسبب يُعرض للمعلم في `message`، ويحدده `code`:

| `code` | المعنى |
|---|---|
| `student_unavailable` | لم يعد الطالب ضمن حلقات المعلم أو لم يعد معتمداً |
| `future_date` | اليوم لم يأتِ بعد |
| `not_working_day` | اليوم ليس من أيام الحلقة في التقويم |
| `not_enrolled` | اليوم قبل التحاق الطالب بالمجمع |
| `inactive_on_date` | لم يكن الطالب مشاركاً في ذلك اليوم |
| `reason_required` | يلزم ذكر سبب التعديل |
| `busy` | تعديل متزامن على الخانة نفسها؛ يُعاد إرساله لاحقاً |

## 5. رصد البنود

- **المسار:** `/api/v1/teacher/scores/changes`
- **البروتوكول:** `POST`

```json
{
  "changes": [
    { "id": "6b0f…", "competition_id": 13, "criterion_id": 41, "student_id": 5, "date": "2026-09-30", "scored": true }
  ]
}
```

- `scored`: الحالة المطلوبة للبند — `true` لمنحه و`false` لإلغائه — لا «قلب» لحالته؛ لذا فإعادة الإرسال، أو أن يسبقك زميل للمنح نفسه، لا تكرر شيئاً ولا تُحدث تعارضاً.
- يُطبَّق كما في صفحة الرصد على الويب: منح البند يحتسب نقاطه وعملاته في المسابقات التحفيزية، وإلغاؤه يسحبها ويعيد حساب الأوسمة.

```json
{ "data": { "results": [ { "id": "6b0f…", "result": "applied", "scored": true } ], "server_time": "…" } }
```

| `code` | المعنى |
|---|---|
| `student_unavailable` | الطالب ليس في حلقات المعلم، أو غير معتمد، أو حالته الحالية غير «مشارك» |
| `competition_unavailable` | المسابقة لم تعد الأساسية للتسجيل في حلقة الطالب |
| `criterion_unavailable` | البند ليس من بنود هذه المسابقة (حُذف مثلاً) |
| `future_date` | اليوم لم يأتِ بعد |
| `outside_competition` | اليوم خارج فترة المسابقة، ولا تُحتسب نقاطه |
| `busy` | تعديل متزامن على الخانة نفسها؛ يُعاد إرساله لاحقاً |

## 6. النقاط الإضافية

- **المسار:** `/api/v1/teacher/extra-points/changes`
- **البروتوكول:** `POST`

```json
{
  "changes": [
    { "id": "9c2e…", "action": "add", "competition_id": 13, "student_id": 5, "date": "2026-09-30", "points": 3, "notes": "ساعد زميله في الحفظ" },
    { "id": "1d7a…", "action": "remove", "extra_point_id": 88 },
    { "id": "4f11…", "action": "remove", "extra_point_uuid": "9c2e…" }
  ]
}
```

- **الإضافة (`add`):** `id` معرّف يولّده التطبيق ويُحفظ في عمود `uuid`، فإرسالها مرتين لا يضيف سجلاً ثانياً. النقاط عدد صحيح من 1 إلى 1000، والسبب (`notes`) إلزامي. تُرفض إن كانت النقاط الإضافية غير مفعّلة في المسابقة (`extra_points_disabled`)، وتنطبق عليها قيود الطالب والمسابقة والتاريخ نفسها في رصد البنود.
- **الحذف (`remove`):** بمعرّف الخادم `extra_point_id` أو بمعرّف التطبيق `extra_point_uuid`. حذف سجل محذوف أصلاً يُعدّ مطبَّقاً.

```json
{ "data": { "results": [ { "id": "9c2e…", "result": "applied", "extra_point": { "id": 91, "uuid": "9c2e…", "competition_id": 13, "student_id": 5, "date": "2026-09-30", "points": 3, "notes": "ساعد زميله في الحفظ" } } ] } }
```

## 7. تقييم التسميع

- **المسار:** `/api/v1/teacher/tasmeeh/changes`
- **البروتوكول:** `POST`
- **الصلاحية:** صفحة التسميع (`teacher.tasmeeh`).

```json
{
  "changes": [
    { "id": "5e0b…", "kind": "plan", "day_id": 991, "part": "hifz", "date": "2026-10-01",
      "grade": 0, "recited": null, "base": { "grade": 3, "recited": null } },
    { "id": "a4c2…", "kind": "free", "student_id": 5, "part": "review", "date": "2026-10-01",
      "grade": 2, "recited": { "from": { "surah": 113, "verse": 1 }, "to": { "surah": 112, "verse": 4 } },
      "base": { "grade": null, "recited": null } }
  ]
}
```

- `kind`: `plan` لجزء من يوم في خطة (`day_id`)، أو `free` للتسميع الحر لطالب (`student_id`).
- `grade`: من 0 إلى 3، أو `null` لمسح التقييم. **0 (لم يسمع) قيمة مستقلة** عن عدم التقييم، تُؤرَّخ ولا تمنح نقاطاً ولا تُرسل إشعاراً.
- `recited`: ما سمّعه الطالب فعلاً، أو `null` إن سمّع مقطع اليوم. إرسال مقطع اليوم نفسه يُحفظ `null`.
- `date`: اليوم الذي يقيّم له المعلم؛ يُؤرَّخ التقييم بالوقت الحالي إن كان اليوم، وإلا بمنتصف نهار ذلك اليوم. ولا يتجاوز اليوم الحالي.
- `base`: قيمة الخانة (التقييم والمقطع) كما رآها الهاتف. **إلزامي** ولو كانت قيمه `null`. لا يُقارن إلا التقييم والمقطع.
- `redate` (اختياري): `true` حين يعدّل المعلم تقييماً ظاهراً من جلسة سابقة (مثل «لم يسمع» للمرة الثانية، أو إكمال ورد ناقص بالتقييم نفسه)، فيُسجَّل التقييم لليوم `date` ولو لم تتغير قيمته. بدونه لا يتغير تاريخ التقييم إلا إذا تغيّر التقييم.
- تحسب النقاط في المسابقات التحفيزية كما في بطاقة التسميع على الويب، والتسميع الحر يُحتسب مثل يوم الخطة. ويُحذف سجل التسميع الحر حين يُفرَّغ تقييمه ومقطعه.

```json
{ "data": { "results": [
  { "id": "5e0b…", "result": "applied", "cell": { "day_id": 991, "part": "hifz", "grade": 0, "recited": null, "graded_at": "…", "graded_on": "2026-10-01", "updated_at": "…", "updated_by": "معلم تجريبي" } },
  { "id": "a4c2…", "result": "conflict", "cell": { "id": 17, "uuid": null, "student_id": 5, "part": "review", "date": "2026-10-01", "grade": 1, "recited": { "…": "…" }, "graded_at": "…", "updated_at": "…", "updated_by": "معلم آخر" } }
], "server_time": "…" } }
```

`cell` هي خانة الخادم بعد التطبيق، أو `null` إن لم يعد فيها شيء. نتائج `applied` و`conflict` كما في التحضير.

| `code` | المعنى |
|---|---|
| `student_unavailable` | لم يعد الطالب ضمن حلقات المعلم أو لم يعد معتمداً |
| `day_unavailable` | حُذف اليوم من خطة الطالب |
| `invalid_part` | الجزء ليس في نوع الخطة |
| `invalid_range` | سورة أو آية غير موجودة |
| `range_required` | تقييم تسميع حر بمقبول فأعلى دون تحديد ما سمّعه |
| `busy` | تعديل متزامن على الخانة نفسها؛ يُعاد إرساله لاحقاً |

## 8. جدولة الاختبارات

- **المسار:** `/api/v1/teacher/exams/changes`
- **البروتوكول:** `POST`
- **الصلاحية:** صفحة اختبارات الطلاب (`teacher.student-exams`).

```json
{
  "changes": [
    { "id": "e7d1…", "action": "create", "student_id": 5, "exam": { "id": null, "uuid": "e7d1…" },
      "level_id": 3, "date": "2026-10-11", "base": null, "edited_on": "2026-10-01" },
    { "id": "0b9f…", "action": "update", "student_id": 6, "exam": { "id": 40, "uuid": null },
      "level_id": 4, "date": "2026-10-18", "base": { "level_id": 3, "date": "2026-10-11" }, "edited_on": "2026-10-01" }
  ]
}
```

- التطبيق يجدول فقط: المستوى واليوم. النتيجة والمكان والملاحظات تبقى لصفحة الويب.
- **الإنشاء:** `id` يُحفظ في عمود `uuid`، فإعادة الإرسال لا تجدول مرتين. الطالب ينتظر اختباراً واحداً، فإن كان له اختبار معلّق عاد `conflict` بذلك الاختبار. يُرسل للطالب إشعار «اختبار جديد مجدول».
- **التعديل:** بمعرّف الخادم `exam.id` أو بمعرّف التطبيق `exam.uuid`، ويلزم `base`. يتغير اليوم ويبقى الوقت الذي حدّدته صفحة الويب. ولا يُرسل إشعار.
- يُحكم على مضيّ اليوم بيوم التعديل `edited_on`، فالاختبار الذي حُدّد لليوم نفسه دون اتصال لا يُرفض لوصوله غداً.

```json
{ "data": { "results": [ { "id": "e7d1…", "result": "applied", "exam": { "id": 41, "uuid": "e7d1…", "student_id": 5, "level_id": 3, "status": "pending", "date": "2026-10-11", "date_hijri": "…", "location": null, "updated_at": "…" } } ], "server_time": "…" } }
```

| `code` | المعنى |
|---|---|
| `student_unavailable` | لم يعد الطالب ضمن حلقات المعلم أو لم يعد معتمداً |
| `exam_level_unavailable` | مستوى الاختبار غير موجود |
| `exam_unavailable` | الاختبار المطلوب تعديله حُذف أو ليس لطالب في حلقات المعلم |
| `exam_closed` | رُصدت نتيجة الاختبار أو أُلغي؛ يُعاد معه `exam` |
| `date_in_past` | اليوم مضى |
| `busy` | تعديل متزامن على اختبار الطالب نفسه؛ يُعاد إرساله لاحقاً |

## 9. إنشاء الخطط القرآنية

- **المسار:** `/api/v1/teacher/plans/changes`
- **البروتوكول:** `POST`
- **الصلاحية:** صفحة إنشاء الخطط (`teacher.plan-creator`).

يكتب التطبيق الخطة دون اتصال بنسخة من محرك الخطط في الموقع (`QuranPlanService` و`QuranPlanFiller`)، فتُحفظ أيامها كما بناها التطبيق: يُتحقق منها ولا يُعاد حسابها. يحرس التطابقَ بين المحركين أمرُ `php artisan app:export-plan-engine` الذي يكتب تخطيط المصحف للتطبيق وإجابات الموقع التي تعيد اختبارات التطبيق تشغيلها.

```json
{
  "changes": [
    { "id": "3f2a…", "student_id": 5, "plan_type": "hifz_review", "direction": "reverse", "review_direction": "reverse",
      "start_date": "2026-10-11", "active_days": ["Sunday", "Monday", "Tuesday", "Wednesday"], "description": null,
      "deactivate_previous": false, "synced_at": "2026-10-09T13:00:00.000Z",
      "days": [
        { "date": "2026-10-11", "hifz": { "from": { "surah": 114, "verse": 1 }, "to": { "surah": 114, "verse": 6 } }, "review": { "from": { "surah": 114, "verse": 1 }, "to": { "surah": 114, "verse": 1 } } }
      ] }
  ]
}
```

- `id` يُحفظ في عمود `uuid`، فإعادة الإرسال لا تحفظ الخطة مرتين. الدفعة حتى ٥٠ خطة، والخطة حتى ١٠٠ يوم.
- تُحفظ الخطة مفعّلة ومعتمدة كخطة المعلم في الموقع، ولا يُحفظ من الأجزاء إلا ما يجدوله نوع الخطة.
- `deactivate_previous` يوقف خطط الطالب المفعّلة الأخرى عند الحفظ الأول فقط، لا عند إعادة الإرسال.
- `synced_at` وقت الخادم في آخر مزامنة بُنيت عليها الخطة: يعود في `created_meanwhile` ما أُنشئ للطالب بعده وقبل هذه الخطة (من الموقع أو من الطالب) ليُنبَّه المعلم، والخطة محفوظة على كل حال.

```json
{ "data": { "results": [ { "id": "3f2a…", "result": "applied", "plan_id": 387,
  "created_meanwhile": [ { "id": 386, "plan_type": "review", "start_date": "2026-10-10", "created_by_role": "student", "status": "active" } ] } ], "server_time": "…" } }
```

| `code` | المعنى |
|---|---|
| `student_unavailable` | لم يعد الطالب ضمن حلقات المعلم (حلقاته هو لا الحلقات التي ينوب فيها) أو لم يعد معتمداً |
| `invalid_plan` | أيام غير مرتبة أو تسبق بداية الخطة، أو آية غير موجودة في جزء يجدوله نوع الخطة |
| `busy` | تُحفظ خطة أخرى للطالب نفسه في اللحظة ذاتها؛ يُعاد إرساله لاحقاً |

## رموز الأخطاء العامة في v1

- `401`: الرمز غير صالح أو أُلغي؛ يعود التطبيق لشاشة الدخول دون حذف تعديلاته المحلية.
- `403` مع `code`:
  - `not_approved`: سُحب تفعيل الحساب.
  - `page_disabled`: أوقفت الإدارة الصفحة للمعلمين (صفحة التحضير للمزامنة والتحضير، وصفحة رصد البنود للبنود والنقاط الإضافية، وصفحة التسميع `teacher.tasmeeh` لتقييم التسميع، وصفحة اختبارات الطلاب `teacher.student-exams` لجدولة الاختبارات، وصفحة إنشاء الخطط `teacher.plan-creator` لإنشاء الخطط).
  - `not_teacher`: الرمز لا يخص معلماً.
- `422`: بيانات الطلب غير صالحة.
- `429`: تجاوز حد الطلبات (١٢٠ طلباً في الدقيقة لكل مجموعة من نقاط المزامنة والتعديلات).
