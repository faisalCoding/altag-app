# دليل واجهات برمجة التطبيقات (API Reference) - المعلم والتحضير

يوفر هذا المستند توثيقاً للمنافذ البرمجية (API Endpoints) الخاصة بتسجيل دخول المعلمين وتحضير الطلاب.

---

## 1. تسجيل دخول المعلم (Teacher Login)

- **المسار:** `/api/teacher/login`
- **البروتوكول:** `POST`
- **الترويسة (Headers):** 
  - `Accept: application/json`
  - `Content-Type: application/json`

### جسم الطلب (Request Body):
```json
{
  "email": "teacher@example.com",
  "password": "password",
  "device_name": "iphone_15"
}
```
*(ملاحظة: حقل `device_name` اختياري ويستخدم لتسمية توكن التوثيق)*

### رد النجاح (200 OK):
```json
{
  "token": "1|abcdef123456...",
  "teacher": {
    "id": 1,
    "name": "معلم تجريبي",
    "email": "teacher@example.com",
    "phone": "123456789",
    "is_approved": true
  }
}
```

### رد الخطأ - بيانات خاطئة (401 Unauthorized):
```json
{
  "message": "بيانات الدخول غير صحيحة."
}
```

### رد الخطأ - حساب غير مفعل (403 Forbidden):
```json
{
  "message": "لم يتم تفعيل حسابك من قبل الإدارة بعد."
}
```

## 2. عرض الحلقات والتحضير (Fetch Circles & Students)

يستخدم لجلب قائمة الحلقات المرتبطة بالمعلم، وقائمة طلاب الحلقة المختارة مع حالة حضورهم الحالية، أو لمزامنة البيانات محلياً.

- **المسار:** `/api/teacher/attendance`
- **البروتوكول:** `GET`
- **الترويسة (Headers):**
  - `Accept: application/json`
  - `Authorization: Bearer <TOKEN>`

### معاملات الاستعلام (Query Parameters):
- `circle_id` (اختياري - integer): معرف الحلقة المراد جلب طلابها.
- `date` (اختياري - string): تاريخ التحضير بتنسيق `YYYY-MM-DD` (القيمة الافتراضية: تاريخ اليوم).
- `last_synced_at` (اختياري - string): توقيت آخر مزامنة بتنسيق ISO 8601 (مثل `2026-06-21T18:00:00Z`). عند إرساله، سيعيد الـ API السجلات المحدثة أو المضافة بعد هذا التوقيت فقط لجميع حلقات المعلم.

### رد النجاح - الاستعلام العام (بدون تحديد حلقة وبدون مزامنة):
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "selected_circle": null,
  "students": []
}
```

### رد النجاح - عند إرسال معرف الحلقة والتاريخ:
`/api/teacher/attendance?circle_id=1&date=2026-06-21`
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "selected_circle": {
    "id": 1,
    "name": "حلقة الإيمان",
    "description": "مخصصة للمرحلة الثانوية"
  },
  "students": [
    {
      "id": 5,
      "name": "طالب تجريبي",
      "circle_id": 1,
      "attendance_status": "present"
    }
  ]
}
```
*(ملاحظة: قيم `attendance_status` الممكنة هي: `present`, `absent`, `late`, `excused` أو نص فارغ `""` في حال لم يحضر الطالب بعد).*

### رد النجاح - عند المزامنة التدريجية (باستخدام `last_synced_at`):
`/api/teacher/attendance?last_synced_at=2026-06-21T18:00:00Z`
```json
{
  "circles": [
    {
      "id": 1,
      "name": "حلقة الإيمان",
      "description": "مخصصة للمرحلة الثانوية"
    }
  ],
  "students": [
    {
      "id": 5,
      "name": "طالب تجريبي",
      "circle_id": 1,
      "attendance_status": ""
    }
  ],
  "attendances": [
    {
      "id": 10,
      "student_id": 5,
      "teacher_id": 1,
      "circle_id": 1,
      "date": "2026-06-21",
      "status": "present",
      "notes": null,
      "updated_at": "2026-06-21T18:30:00.000000Z"
    }
  ],
  "server_time": "2026-06-21T18:45:25.000000Z"
}
```
*(ملاحظة: حقل `attendance_status` في الطلاب المسترجعين عند المزامنة التدريجية يكون فارغاً، حيث يتم الاعتماد على مصفوفة الـ `attendances` المرفقة لبناء السجل المحلي).*

### رد الخطأ - حلقة غير تابعة للمعلم (403 Forbidden):
```json
{
  "message": "غير مصرح لك بالوصول لهذه الحلقة."
}
```

## 3. رصد وحفظ حضور الطلاب (Mark Student Attendance)

يستخدم لحفظ أو تحديث حضور وغياب الطلاب في حلقة وتاريخ محددين، أو لمزامنة البيانات محلياً.

- **المسار:** `/api/teacher/attendance`
- **البروتوكول:** `POST`
- **الترويسة (Headers):**
  - `Accept: application/json`
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>`

### جسم الطلب (Request Body):

يدعم المنفذ طريقتين للطلب لضمان توافقية الأنظمة:

#### الطريقة الأولى: الإرسال البسيط لمجموعة طلاب (Associative Array)
```json
{
  "circle_id": 1,
  "date": "2026-06-21",
  "records": {
    "5": "present",
    "6": "late",
    "7": "absent"
  }
}
```
*(ملاحظة: هيكل الـ `records` هو عبارة عن قاموس يربط معرف الطالب `student_id` بحالة الحضور المقررة له: `present`, `absent`, `late`, `excused`).*

#### الطريقة الثانية: المزامنة الدفعية للمحلي أولاً (Local-First Batch Sync)
تسمح بمزامنة سجلات لتواريخ وحلقات مختلفة مع دعم فرز التعارضات بالتوقيت:
```json
{
  "records": [
    {
      "student_id": 5,
      "status": "present",
      "date": "2026-06-21",
      "updated_at": "2026-06-21T18:30:00Z"
    },
    {
      "student_id": 6,
      "status": "absent",
      "date": "2026-06-20",
      "updated_at": "2026-06-21T18:25:00Z"
    }
  ]
}
```
*(ملاحظة: يقوم النظام بتطبيق خوارزمية **"آخر كتابة تفوز" (Last-Write-Wins)** بمقارنة `updated_at` الممررة مع نظيرتها في قاعدة البيانات. يتم تخطي التحديث إذا كانت النسخة على السيرفر أحدث).*

### رد النجاح (200 OK):
```json
{
  "message": "تم تسجيل حضور الطلاب بنجاح.",
  "synced_attendances": [
    {
      "id": 10,
      "student_id": 5,
      "teacher_id": 1,
      "circle_id": 1,
      "date": "2026-06-21",
      "status": "present",
      "notes": null,
      "updated_at": "2026-06-21T18:45:25.000000Z"
    }
  ]
}
```

### رد الخطأ - عدم صلاحية الحلقة (403 Forbidden):
```json
{
  "message": "غير مصرح لك بالوصول لهذه الحلقة."
}
```

# الإصدار الأول (v1) — تطبيق المعلم بالعمل دون اتصال

صُمّم هذا الإصدار لتطبيق الجوال الذي يحفظ بياناته كاملةً على الهاتف ويعمل دون اتصال، ثم يزامنها مع الخادم. المنافذ السابقة أعلاه باقية كما هي.

- **الفكرة:** يجلب التطبيق نسخة كاملة من بياناته من `/sync` ويستبدل بها نسخته المحلية في كل مزامنة، ويحفظ تعديلات التحضير في طابور على الهاتف ثم يرسلها إلى `/attendance/changes`.
- **الترويسة (Headers)** لجميع المنافذ:
  - `Accept: application/json`
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>` (عدا تسجيل الدخول)
- **التاريخ:** جميع التواريخ بتنسيق `YYYY-MM-DD`، و«اليوم» يُحسب بتوقيت الرياض (`Asia/Riyadh`).

## 1. تسجيل الدخول

- **المسار:** `/api/v1/teacher/login`
- **البروتوكول:** `POST`
- **الحد:** ٥ محاولات في الدقيقة لكل بريد وعنوان IP.

```json
{
  "email": "teacher@example.com",
  "password": "password",
  "device_name": "Pixel 9"
}
```

### رد النجاح (200 OK):
```json
{
  "data": {
    "token": "1|abcdef123456...",
    "teacher": { "id": 1, "name": "معلم تجريبي", "email": "teacher@example.com", "phone": "0500000000", "is_approved": true }
  }
}
```

ردود الخطأ: `401` لبيانات خاطئة، و`403` لحساب لم تُفعّله الإدارة. الرمز لا تنتهي صلاحيته حتى يُسجَّل الخروج.

## 2. تسجيل الخروج

- **المسار:** `/api/v1/teacher/logout`
- **البروتوكول:** `POST`

يُلغي الرمز المستخدم في الطلب فقط، وتبقى أجهزة المعلم الأخرى مسجّلة.

## 3. جلب البيانات للعمل دون اتصال (Sync)

- **المسار:** `/api/v1/teacher/sync`
- **البروتوكول:** `GET`

يعيد كل ما يحتاجه التطبيق لتحضير الطلاب دون اتصال:

- `today`: تاريخ اليوم بتوقيت الرياض.
- `window`: نطاق البيانات؛ يبدأ `from` من أول الشهر الهجري السابق، وينتهي `to` بعد اليوم بأربعة عشر يوماً حتى يستمر التحضير إن انقطع الاتصال.
- `circles`: حلقات المعلم، ولكل حلقة `require_edit_reason` (هل يُطلب سبب للتعديل في غير يوم الجلسة) و`working_days` (أيام الحلقة في التقويم ضمن النطاق).
- `students`: طلاب الحلقات المعتمدون مع `joined_at` وسجل حالاتهم `status_histories`، لتحديد الأيام التي يجوز تحضيرهم فيها.
- `attendances`: سجلات حضور هؤلاء الطلاب من بداية النطاق حتى اليوم، أياً كانت الحلقة التي سجّلتها.
- `days`: قراءة كل يوم في النطاق بالتاريخ الهجري (أم القرى).
- `labels`: مسميات حالات الحضور وحالات الطالب.
- `competitions`: المسابقة الأساسية للتسجيل لكل حلقة — مسابقة المشرف المعيّنة كأساسية للحلقة، وإلا مسابقة المعلم الخاصة المعيّنة كأساسية — مع بنودها (`criteria`) وفترتها، وهل النقاط الإضافية مفعّلة فيها، وحلقات المعلم التي تُرصد فيها (`circle_ids`).
- `scores`: البنود الممنوحة للطلاب داخل النطاق؛ وجود السجل يعني أن البند ممنوح.
- `extra_points`: النقاط الإضافية داخل النطاق، ولكل منها `id` على الخادم و`uuid` إن أُنشئت من التطبيق.

```json

    "today": "2026-10-01",
    "window": { "from": "2026-08-14", "to": "2026-10-15" },
    "teacher": { "id": 1, "name": "معلم تجريبي", "email": "teacher@example.com", "phone": null, "is_approved": true },
    "circles": [
      {
        "id": 3, "name": "حلقة الإيمان", "description": null,
        "stage": { "id": 1, "name": "المرحلة الثانوية" },
        "require_edit_reason": true,
        "working_days": ["2026-08-16", "2026-08-17"]
      }
    ],
    "students": [
      {
        "id": 5, "name": "طالب تجريبي", "circle_id": 3, "status": "active",
        "joined_at": "2026-08-20", "joined_at_hijri": "٧ ربيع الأول ١٤٤٨",
        "status_histories": [
          { "id": 9, "status": "suspended", "start_date": "2026-09-10", "start_date_hijri": "٢٨ ربيع الأول ١٤٤٨" }
        ]
      }
    ],
    "attendances": [
      { "student_id": 5, "circle_id": 3, "date": "2026-09-30", "status": "present", "updated_at": "2026-09-30T13:05:00.000000Z", "updated_by": "معلم تجريبي" }
    ],

      "2026-10-01": { "weekday": "الخميس", "day": "٢٠", "month": "ربيع الآخر ١٤٤٨", "full": "الخميس، ٢٠ ربيع الآخر ١٤٤٨" }

      "attendance": { "present": "حاضر", "absent": "غائب", "late": "متأخر", "excused": "مستأذن" },
```

## 4. إرسال تعديلات التحضير

- **المسار:** `/api/v1/teacher/attendance/changes`
- **البروتوكول:** `POST`
- **الحد:** حتى ٥٠٠ تعديل في الطلب الواحد.

```json
{
  "changes": [
    {
      "id": "2f1c9a4e-8b7d-4c1e-9f3a-6d2b1e0c5a7f",
      "student_id": 5,
      "date": "2026-09-30",
      "status": "present",
      "base_status": null,
      "reason": "نسيت التحضير في يومه",
      "edited_on": "2026-10-01"
    }
  ]
}
```

- `id`: معرّف UUID يولّده الهاتف لكل تعديل، ويُعاد في الرد لربط النتيجة بالتعديل.
- `status`: الحالة الجديدة، أو `null` لمسح التحضير.
- `base_status`: الحالة التي رآها الهاتف على الخادم عند التعديل (أو `null` إن لم يكن هناك تسجيل). **حقل إلزامي** ولو كانت قيمته `null`.
- `reason`: سبب التعديل، ويُطلب إذا كان اليوم المُحضَّر غير يوم التعديل وكانت مرحلة الحلقة تشترطه.
- `edited_on`: اليوم الذي أجرى فيه المعلم التعديل على هاتفه؛ فالتحضير الذي يُسجَّل في يومه دون اتصال ثم يُزامَن لاحقاً لا يُعدّ تعديلاً في غير يوم الجلسة.

تُطبَّق على كل تعديل قواعد صفحة التحضير الشهرية نفسها، ويُسجَّل في سجل التعديلات كما لو أُجري من الصفحة.

### رد النجاح (200 OK):
```json
{
  "data": {
    "results": [
      { "id": "2f1c…", "result": "applied", "attendance": { "student_id": 5, "circle_id": 3, "date": "2026-09-30", "status": "present", "updated_at": "…", "updated_by": "معلم تجريبي" } },
      { "id": "7a3d…", "result": "conflict", "attendance": { "student_id": 6, "circle_id": 3, "date": "2026-09-30", "status": "absent", "updated_at": "…", "updated_by": "معلم آخر" } },
      { "id": "c91e…", "result": "rejected", "code": "reason_required", "message": "يجب إدخال سبب التعديل عند التحضير في غير يوم الجلسة." }
    ],
    "server_time": "2026-10-01T07:40:00.000000Z"
  }
}
```

**أنواع النتائج:**

- `applied`: حُفظ التعديل، أو كان الخادم يحمل القيمة نفسها مسبقاً. لذلك فإن إعادة إرسال تعديل حُفظ من قبل لا تكرّره.
- `conflict`: تغيّرت القيمة على الخادم منذ آخر مزامنة (من معلم آخر أو من صفحة الويب) إلى قيمة ثالثة. لا يُحفظ التعديل، ويُعاد سجل الخادم الحالي ليعرض التطبيق القيمتين على المعلم فيختار. لاعتماد قيمة الهاتف يُعاد إرسال التعديل بـ `base_status` يساوي قيمة الخادم.
- `rejected`: رُفض التعديل لسبب يُعرض للمعلم في `message`، ويحدده `code`:

| `code` | المعنى |
|---|---|
| `student_unavailable` | لم يعد الطالب ضمن حلقات المعلم أو لم يعد معتمداً |
| `future_date` | اليوم لم يأتِ بعد |
| `not_working_day` | اليوم ليس من أيام الحلقة في التقويم |
| `not_enrolled` | اليوم قبل التحاق الطالب بالمجمع |
| `inactive_on_date` | لم يكن الطالب مشاركاً في ذلك اليوم |
| `reason_required` | يلزم ذكر سبب التعديل |
| `busy` | تعديل متزامن على الخانة نفسها؛ يُعاد إرساله لاحقاً |

## 5. رصد البنود

- **المسار:** `/api/v1/teacher/scores/changes`
- **البروتوكول:** `POST`

```json
{
  "changes": [
    { "id": "6b0f…", "competition_id": 13, "criterion_id": 41, "student_id": 5, "date": "2026-09-30", "scored": true }
  ]
}
```

- `scored`: الحالة المطلوبة للبند — `true` لمنحه و`false` لإلغائه — لا «قلب» لحالته؛ لذا فإعادة الإرسال، أو أن يسبقك زميل للمنح نفسه، لا تكرر شيئاً ولا تُحدث تعارضاً.
- يُطبَّق كما في صفحة الرصد على الويب: منح البند يحتسب نقاطه وعملاته في المسابقات التحفيزية، وإلغاؤه يسحبها ويعيد حساب الأوسمة.

```json
{ "data": { "results": [ { "id": "6b0f…", "result": "applied", "scored": true } ], "server_time": "…" } }
```

| `code` | المعنى |
|---|---|
| `student_unavailable` | الطالب ليس في حلقات المعلم، أو غير معتمد، أو حالته الحالية غير «مشارك» |
| `competition_unavailable` | المسابقة لم تعد الأساسية للتسجيل في حلقة الطالب |
| `criterion_unavailable` | البند ليس من بنود هذه المسابقة (حُذف مثلاً) |
| `future_date` | اليوم لم يأتِ بعد |
| `outside_competition` | اليوم خارج فترة المسابقة، ولا تُحتسب نقاطه |
| `busy` | تعديل متزامن على الخانة نفسها؛ يُعاد إرساله لاحقاً |

## 6. النقاط الإضافية

- **المسار:** `/api/v1/teacher/extra-points/changes`
- **البروتوكول:** `POST`

```json
{
  "changes": [
    { "id": "9c2e…", "action": "add", "competition_id": 13, "student_id": 5, "date": "2026-09-30", "points": 3, "notes": "ساعد زميله في الحفظ" },
    { "id": "1d7a…", "action": "remove", "extra_point_id": 88 },
    { "id": "4f11…", "action": "remove", "extra_point_uuid": "9c2e…" }
  ]
}
```

- **الإضافة (`add`):** `id` معرّف يولّده التطبيق ويُحفظ في عمود `uuid`، فإرسالها مرتين لا يضيف سجلاً ثانياً. النقاط عدد صحيح من 1 إلى 1000، والسبب (`notes`) إلزامي. تُرفض إن كانت النقاط الإضافية غير مفعّلة في المسابقة (`extra_points_disabled`)، وتنطبق عليها قيود الطالب والمسابقة والتاريخ نفسها في رصد البنود.
- **الحذف (`remove`):** بمعرّف الخادم `extra_point_id` أو بمعرّف التطبيق `extra_point_uuid`. حذف سجل محذوف أصلاً يُعدّ مطبَّقاً.

```json
{ "data": { "results": [ { "id": "9c2e…", "result": "applied", "extra_point": { "id": 91, "uuid": "9c2e…", "competition_id": 13, "student_id": 5, "date": "2026-09-30", "points": 3, "notes": "ساعد زميله في الحفظ" } } ] } }
```

## رموز الأخطاء العامة في v1

- `401`: الرمز غير صالح أو أُلغي؛ يعود التطبيق لشاشة الدخول دون حذف تعديلاته المحلية.
- `403` مع `code`:
  - `not_approved`: سُحب تفعيل الحساب.
  - `page_disabled`: أوقفت الإدارة الصفحة للمعلمين (صفحة التحضير للمزامنة والتحضير، وصفحة رصد البنود للبنود والنقاط الإضافية).
  - `not_teacher`: الرمز لا يخص معلماً.
- `422`: بيانات الطلب غير صالحة.
- `429`: تجاوز حد الطلبات (١٢٠ طلباً في الدقيقة لكل مجموعة من نقاط المزامنة والتعديلات).
